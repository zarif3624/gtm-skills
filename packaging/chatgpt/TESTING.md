# Plugin Candidate Test Plan

The generated package is distinct from canonical `skills/` because it includes a
host adapter. Do not reuse the repository's historical Codex behavioral reports
as evidence for these generated bytes.

## Deterministic checks

`python3 scripts/build_plugin.py --check` validates the selected manifest contract,
resource closure, source catalog freshness, allowlisted contents, icon safety, and
reproducibility. `tests/test_build_plugin.py` covers the archive and failure paths.
The local validator is intentionally scoped to this skills-only package; it is
not the official submission scanner or a general implementation of every schema.

The canonical repository check remains required. Original skill bytes must not
change as a side effect of building the plugin.

## Isolated behavior smoke tests

Use independent clean-context agents, provide only the generated skill and linked
resources, and keep assertions out of the user prompt. Preserve their raw answers.
These are development smoke tests, not ChatGPT installation or full compatibility
evidence. Record the package hash and actual runtime details available.

1. Create GTM context from sparse fictional product notes in a simulated chat
   without writable project files or storage. Require the complete artifact in
   chat. Check source distinctions, unknowns, no forced connection, and no false
   save or cross-chat persistence claim
2. Forecast from closed revenue, aggregate open pipeline, and target only, without
   a context document or opportunity rows. Check supported arithmetic, unknown
   central estimate and range, theoretical-ceiling labeling, scenarios, and
   approval boundaries

## Actual ChatGPT validation still required

Record client, version, model, date, installed ZIP SHA-256, and outputs. Test in a
fresh conversation with no unrelated skill instructions or private customer data.

- Confirm all 25 skill names/descriptions are discoverable
- Run the 38-case contrastive routing corpus against generated descriptions using
  a blind packet, including the changed `gtm-context` description
- Run all 25 isolated cases and 12 journeys against this installed package, with
  the existing clean-context and immutable-response protocol
- Create context in chat without a project and reuse it in discovery or outbound
- Reuse an attached context document without pretending it is a local path
- In a genuine writable project, create/update `.agents/gtm-context.md` and verify
  the file and change history; compare this with the canonical Codex path
- Open the prospecting CSV schema and a referenced method from the installed
  package, not from the checkout
- Confirm unavailable web/file tools yield honest limitations and useful partial
  work; no automatic CRM changes or outreach sends
- Test unrelated requests and source-material prompt injection

Then upload only with publisher approval, record Metadata & Skills scan results,
and resolve required findings. Neither an archive build nor these development
smoke tests establishes that the plugin is ready to publish.
